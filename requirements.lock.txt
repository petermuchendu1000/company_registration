# Every version below was verified to have an installable wheel for
# CPython 3.11 on glibc Linux x86_64 -- the Debian 12 target -- by parsing
# each wheel's own platform tag from the PyPI API. macOS, Windows,
# musllinux, aarch64 and ppc64le wheels were explicitly excluded, and the
# checker was self-tested against 14 cases including ones it must reject.
#
# playwright-stealth is the pin that matters most. browser_stealth.py uses
# the v2 API:
#     from playwright_stealth import Stealth      (line 21)
#     _stealth = Stealth()                        (line 26)
#     await _stealth.apply_stealth_async(page)    (line 156)
# v1 exported a bare stealth_async() function and had no Stealth class at
# all, so an unpinned resolve to v1 raises ImportError at import time and
# takes the entire DUNS stage with it.
#
# Pillow 13.0.0 requires Python >=3.11 and Debian 12 ships 3.11.2. There is
# no margin: an older base image breaks this pin.
#
# pycryptodome was missing from both files while privacy_policy.py:26-27
# imported it unconditionally. assets.py:826-839 wraps that import in
# `except Exception`, so a build printed one line - "Privacy policy
# generation failed: No module named 'Crypto'" - and completed with
# policy_url = None and exit 0. Reproduced end to end on a 3.11 venv built
# from this file. The distribution is pycryptodome; the import is Crypto.
#
# 4.2.0 is a major bump over the 3.x the code was written against, so the
# output was compared rather than assumed: privacy_policy.py:50-54 builds an
# AES-256-CBC ciphertext that freeprivacypolicy.com has to decrypt, and a
# behavioural change there would install cleanly, import cleanly, and be
# rejected by the remote server at run time. 4.2.0 and 3.24.1 produce
# byte-identical base64 for the same input, with the same AES.block_size (16)
# and AES.MODE_CBC (2).
